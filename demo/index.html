Consent state: waiting for a choice.

How this actually blocks marketing and analytics

This banner only becomes real consent enforcement when optional tags are loaded through the consent layer. If a script is added normally with a regular <script src="...">, it will load before the user has a choice.

The correct pattern

  • Use type="text/plain" so the browser does not execute the script immediately.
  • Add data-consent-category="analytics" or data-consent-category="marketing".
  • The banner turns that blocked tag into a real script only after that category is accepted.
<script
  type="text/plain"
  data-consent-category="marketing"
  data-consent-src="https://example.com/meta-pixel-or-ads.js"
  async>
</script>

What happens if the user rejects marketing?

  • The consent state is saved with marketing: false.
  • Any blocked marketing script stays blocked.
  • Your ad or pixel code does not run.

Example noob-friendly setup

<link rel="stylesheet" href="/cookie-banner.css">

<script
  type="text/plain"
  data-consent-category="analytics"
  data-consent-src="https://www.googletagmanager.com/gtag/js?id=G-XXXXXXX"
  async>
</script>

<script type="text/plain" data-consent-category="analytics">
  window.dataLayer = window.dataLayer || [];
  function gtag(){dataLayer.push(arguments);}
  gtag('js', new Date());
  gtag('config', 'G-XXXXXXX');
</script>

<script type="module">
  import { initCookieBanner } from "/cookie-banner.js";

  initCookieBanner({
    policyUrl: "/privacy-policy",
    consentVersion: "2026-04"
  });
</script>
